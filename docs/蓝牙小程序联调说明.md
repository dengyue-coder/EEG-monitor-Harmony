## 端到端测试步骤

1. 用 DevEco Studio 打开 `本仓库 app/ 工程（优化版 UI）`，编译安装到平板/手机（需自行配置签名）。
2. App 内打开**监护者模式 → 设备页**，点"开启"启动小程序接收模式（或个人模式顶部点"小程序"开关）。
3. 用微信开发者工具导入 `本地小程序模拟端（未纳入本仓库）`，真机预览（手机与平板在同一蓝牙范围）。
4. 小程序首页点"蓝牙发送到 App" → "扫描设备" → 选择目标设备（列表中标绿点/提示"目标设备"的即为 App）→ 连接 → "开始发送"。
5. App 端即可看到帧数增长、实时数据预览；"小程序"设备会出现在设备列表/监测页，个人模式可切换到该设备查看脑波、情绪等全部页面。

## 通信协议（两端一致，勿改）

| 项 | 值 |
|----|----|
| Service UUID | `0000EE01-0000-1000-8000-00805F9B34FB` |
| Characteristic UUID | `0000EE02-0000-1000-8000-00805F9B34FB` |
| 写方式 | write with response（小程序侧 `writeType: 'write'`） |
| 数据格式 | EEG JSON 帧：`{"sig":0,"att":55,"med":40,"raw":...,"d":...,"t":...,"aL":...,"aH":...,"bL":...,"bH":...,"gL":...,"gM":...}` |
| 帧间隔 | 小程序默认 300ms（可改 `blelink.js` 的 `FRAME_INTERVAL`） |

小程序会优先协商 MTU=247 让整帧一次写入；协商失败自动回退 20 字节分片，App 端自动拼帧。

## UI 架构：真实设备（蓝牙） vs 演示（小程序模拟）

App 的数据来源分为两类，界面上已明确分层：

- **真实设备（蓝牙）**：监护者模式 →「设备」页「蓝牙 BLE」区——扫描、连接、断开多台真实脑环；「监测」页展示所有在线设备并标注「真实」标签；教师头部显示「真实 N 台」。
- **演示（小程序模拟）**：「设备」页下半区「演示 · 小程序模拟」——标注"比赛体验用"，供评委在比赛中通过手机小程序体验；接收到的数据在设备列表中标注「演示」。

个人模式顶部设备栏同样显示当前设备的「真实/演示」标签，「演示」按钮控制小程序接收开关。

## 常见问题

- 扫描不到设备：确认 App 端接收模式处于"已开启"状态、手机蓝牙已开、两者距离较近。
- 连接后不涨帧数：确认 App 端没有其它设备占用蓝牙服务；可先断开再重连。
- 提示"未找到 EE01 服务"：App 端接收模式未开启，或两台设备不在同一蓝牙范围。
- 编译报错：本副本缺少 DevEco 生成的 `local.properties`/签名，首次打开 DevEco 时自动补齐即可。
