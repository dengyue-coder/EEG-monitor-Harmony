# 小熊派 H3863 蓝牙（BLE）真机联调说明

## 1. 本版架构：只保留蓝牙

小熊派 BearPi 使用 H3863（WS63）双模芯片，同时支持 BLE 5.2 与星闪 SLE 1.0，
两套协议互不可见。**本版 App 已移除全部星闪（NearLink）代码**：

- 删除 `service/NearLinkService.ets`（星闪扫描 / SSAP 连接 / 属性通知）。
- 移除 `ohos.permission.ACCESS_NEARLINK` 权限声明与动态申请。
- 设备页回归纯蓝牙扫描；真实设备数据通道全部走 BLE。

App 通过蓝牙连接小熊派后，按以下顺序自动匹配数据特征：

1. 精确匹配脑环专用服务 `0000EE01-...` / 特征 `0000EE02-...`（本 App 自定义 EEG JSON 协议）。
2. 匹配 UART 透传类服务，**包含小熊派官方 SDK 示例的服务 0xABCD / 通知 0xCDEF**。
3. 兜底：连接后取设备第一个可通知（Notify）特征。

## 2. 联调步骤

1. 平板打开蓝牙；App 启动时已自动申请蓝牙权限（若之前拒绝过，到 设置→应用→本应用→权限 打开蓝牙/附近设备权限）。
2. 打开 App → 监护者模式 → 设备页 → 点"扫描"（蓝牙 BLE）。
3. 列表中找到小熊派设备（官方示例广播名 `ble_uart_server`，固件可自行改名），点"连接"。
4. 连接成功后会出现在"已注册设备"中；佩戴脑环后，脑波、专注度、冥想度实时刷新。

## 3. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 点击"连接"提示连接失败 | App 会显示具体原因：连接超时（15 秒）→ 设备未开机 / 不在广播 / 已被其它设备（如平板系统蓝牙）占用；"已连接但没有可接收数据的特征"→ 固件数据通道不是 Notify/Indicate；"开启数据通知失败"→ 设备要求配对或特征不支持订阅。 |
| 扫描不到设备 | ① 未授予蓝牙权限（设置→权限）。② 小熊派未开机 / 未进入广播状态 / 距离太远。③ 固件实际走的是星闪 SLE，蓝牙永远看不到。 |
| 能连接但一直没有数据 | 数据必须通过"特征通知（Notify）"推送，且格式为 EEG JSON 帧；收到 4KB+ 无法解析时 App 会提示格式不符。 |
| 连接后提示服务清单 | App 会列出设备实际提供的服务 UUID，据此核对固件协议（EE01/EE02 或 0xABCD/0xCDEF）。 |
| 固件只开星闪 SLE | 本版 App 不支持星闪；需将固件改为 BLE 广播/连接（可参考 SDK 的 ble_uart_server 示例）。 |

## 4. 固件侧需确认

1. 脑环固件使用 **BLE** 广播/连接（不是 SLE）。
2. 数据通过哪个服务/特征 Notify 推送（官方示例 0xABCD/0xCDEF，或 EE01/EE02）。
3. 广播名是什么（决定你在列表里认哪个设备）。
4. 数据格式是否为 EEG JSON 帧：`{"sig":0,"att":55,"med":40,"raw":...,"d":...,"t":...,"aL":...,"aH":...,"bL":...,"bH":...,"gL":...,"gM":...}`
